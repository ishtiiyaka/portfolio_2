Kubuntu Linux

The Unrestricted Operating System
01

An operating system shouldn't be a walled garden; it should be a malleable toolchain. My daily driver is Kubuntu (Ubuntu base with the KDE Plasma desktop environment).

Windows and macOS hide system telemetry and restrict low-level hardware access. Linux provides complete visibility. I utilize KDE Plasma because it offers granular customization — allowing me to strip away bloat, implement strict tiling window manager (TWM) scripts, and bind critical engineering workflows directly to keyboard shortcuts.

  • System Level: Direct access to /dev for hardware serial sniffing and custom driver compilation.
  • Resource Efficiency: Idle RAM sits below 1.2GB, leaving maximum computational overhead for CAD simulations and local Docker containers.

Zsh & Powerlevel10k

Zero-Latency Command Line
02

The GUI is a bottleneck. I operate entirely within the terminal using Zsh (Z Shell) heavily customized with the Powerlevel10k theme and rapid-response plugins.

My .zshrc is a curated list of aliases and functions designed to reduce repetitive keystrokes. I utilize zsh-autosuggestions (based on history) and zsh-syntax-highlighting to catch syntax errors before execution.

The Powerlevel10k prompt provides instantaneous visual feedback: current Git branch status, untracked file counts, virtual environment status, and command execution time, ensuring I never have to manually query system state.

CLI-First Git Flow

Architectural Version Control
03

Version control is not just a backup system; it is the architectural blueprint of a project's evolution. I use a strict CLI-first Git workflow — no bloated GUI clients, just raw commands for maximum control.

I maintain clean, linear project histories. Instead of messy merge commits, I enforce interactive rebasing (git rebase -i) to squash trivial commits and reword logs before pushing to upstream repositories.

Every commit is atomic: doing one thing and documenting it clearly. I utilize Git hooks to automate pre-commit code linting and structural checks before hardware builds are triggered.

Cognitive Linguistics

Parsing Human Frameworks
04

I approach human languages exactly how I approach programming languages: as distinct syntactic frameworks for processing data. I am fluent in English, Urdu, and Burushaski.

Burushaski is particularly fascinating. As a language isolate spoken in Gilgit-Baltistan, it has no known linguistic relatives globally. It operates on a highly complex ergative-absolutive alignment and an intricate noun class system. Growing up with this as a mother tongue forged an early capability to parse extremely unconventional data structures.

Navigating between the Latin script (English), the right-to-left Perso-Arabic script (Urdu), and the unwritten acoustic structures of Burushaski allows for rapid cognitive context switching.

Mandarin Chinese (HSK)

Algorithmic Language Acquisition
05

I am currently engineering my acquisition of Mandarin Chinese. Rather than traditional passive learning, I treat the language as a database of visual arrays (Hanzi) and acoustic frequencies (Pinyin tones).

I utilize Spaced Repetition Systems (Anki) with custom-coded card templates to algorithmically force character retention into long-term memory. Recognizing radicals within characters is akin to understanding root functions in software engineering.

Given the global dominance of Chinese manufacturing in the hardware and PCB space (Shenzhen/JLCPCB), acquiring Mandarin directly bypasses translation bottlenecks when reading native datasheets and negotiating hardware fabrication specs.
