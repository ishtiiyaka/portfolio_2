Robotic Vacuum
Diagnostic System

A complete hardware and software forensic ecosystem built to interface directly with undocumented robotic vacuum mainboards. Sniffs UART and serial data streams, reverse-engineers proprietary command packets, and injects custom payloads to achieve full system control without manufacturer documentation.

UART Serial Protocols Hex Analysis CRC Decoding Logic Analyser Packet Injection Python

The Problem: No Documentation Exists

Chinese robotic vacuum manufacturers ship units with custom mainboards running undocumented proprietary firmware. There is no public API, no open serial protocol, and no diagnostic port exposed to the user. The hardware is a sealed black box.

To build a proper diagnostic tool, I had to create the documentation myself — by reading the raw electrical signals directly off the board using a Saleae Logic Analyzer, physically probing unlabeled test points until I identified active UART buses.

Phase 1 — Bus Discovery

  • Physical Probing: Using a multimeter and scope, I identified 3.3V UART activity between the mainboard MCU and the sensor module.
  • Baud Rate Cracking: By capturing the raw signal timing and calculating pulse widths, I deduced a non-standard baud rate of 115200 bps, 8N1.
  • Differential Analysis: Captured 2000+ packet samples during normal operation to identify repeated preamble bytes (0x5A 0xA5) marking packet boundaries.

Phase 2 — Packet Deconstruction

With the bus confirmed, every byte stream was captured during known operations (fan on, navigation start, dock command). By comparing hundreds of captures against corresponding behaviours, I built a packet-map.

The proprietary protocol uses a fixed-header framing scheme: preamble (0x5A 0xA5), a 1-byte command ID, a 1-byte payload length, N payload bytes, and a trailing custom CRC-8 checksum computed against the payload bytes only. I reverse-engineered the CRC polynomial by trial and error against captured packets.

  • Payload Injection: A custom Python bridge (PySerial) rebuilds packets with modified command bytes and injects them onto the bus, overriding vacuum behaviour in real-time.
  • Live Decoder GUI: A Python/Tkinter interface decodes incoming hex streams into human-readable command labels, timestamps, and status indicators.
  • Full Packet Map: Documented 24 unique command IDs covering motor control, sensor polling, error states, and map transmission payloads.
